DISCRETE — BUILTIN FUNCTIONS

Every builtin function discrete ships with. specs.txt ("builtin toolkit")
is the source of truth for how they behave; this file is the developer's
index of what exists and where it lives.

A user adds a builtin with configure -> add a function -> choose builtin
function. The function they create stores the builtin's id (never its
name), plus its argument if it takes one.


TOOLKIT (in display order)

builtin functions/                     (root folder)
    search
    move window to next monitor
    open website
    trackpad functions/
        toggle sketch mode
        activate sketch mode
        deactivate sketch mode
    open application intelligently
    toggle full-screen


search
    id:        search
    argument:  none
    exits:     no (opens state.search, discrete stays active)
    code:      DiscreteGraphStore.openSearch()
    does:      opens the same search as the root's search action. esc goes
               back to the state the function was triggered from.

move window to next monitor
    id:        move-window-to-next-monitor
    argument:  none
    exits:     yes
    code:      discrete/Builtins/WindowMover.swift
    does:      moves the frontmost app's focused window to the next monitor
               (left to right, wrapping around), keeping its size (shrunk to
               fit) and relative place. a maximized window (filling the
               monitor's visible frame, within 8pt) fills the next monitor
               instead. a full-screen window leaves full screen, moves
               (maximized), and goes full screen again (AXFullScreen).
               needs Accessibility permission, which discrete already asks
               for. does nothing with one monitor or no focused window.

open website
    id:        open-website
    argument:  "website url or ip address", asked for right after choosing
               the builtin. does not affect the function's name.
    exits:     yes
    code:      discrete/Builtins/WebsiteOpener.swift
    does:      opens the address in the default browser and brings it to
               the front. a missing scheme becomes http:// for an ip address
               or localhost, https:// otherwise.

trackpad functions/                    (folder)

toggle sketch mode
    id:        toggle-sketch-mode
    argument:  none
    exits:     yes
    code:      discrete/Builtins/SketchMode.swift (SketchMode.toggle)
    does:      turns sketch mode on if it is off, off if it is on.

activate sketch mode
    id:        activate-sketch-mode
    argument:  none
    exits:     yes
    code:      discrete/Builtins/SketchMode.swift (SketchMode.activate)
    does:      turns sketch mode on. nothing changes if it is already on.

deactivate sketch mode
    id:        deactivate-sketch-mode
    argument:  none
    exits:     yes
    code:      discrete/Builtins/SketchMode.swift (SketchMode.deactivate)
    does:      turns sketch mode off. nothing changes if it is already off.

    sketch mode: while on, a single finger on the trackpad draws. the
    pointer goes to the screen point matching the finger's place on the
    trackpad (centre to centre, corner to corner, on the screen under the
    pointer), the left button is held while the finger is down, and lifting
    releases it and leaves the pointer still. two or more fingers work as
    usual. finger positions come from the private MultitouchSupport
    framework (looked up with dlopen; sketch mode stays off if it is
    missing). only contacts the framework recognizes as fingers (finger id
    1-5, thumb to little) count; a resting hand shows up as ids 7 and 10
    pinned to the trackpad's edge and is ignored. an event tap holds back the trackpad's own pointer moves and
    left clicks while a lone finger is down, and for 0.5s after (tap to
    click arrives late); the pointer is detached from the trackpad
    (CGAssociateMouseAndMouseCursorPosition) only while the finger is down. a lone
    finger presses only after 60ms alone, so two-finger gestures don't
    draw dots. sketch mode is not saved: it is off when discrete starts.


open application intelligently
    id:        open-application-intelligently
    argument:  "application name, bundle id, or .app path" (for example,
               Visual Studio Code, com.microsoft.VSCode, or
               /Applications/Visual Studio Code.app). blank or unresolved
               arguments open nothing. the function's name is independent.
    exits:     yes
    code:      discrete/Builtins/ApplicationOpener.swift
               discrete/Builtins/ApplicationOpenPolicy.swift (selection)
               discrete/Builtins/ApplicationWindowSnapshot.swift (visibility)
               discrete/Builtins/ApplicationSpaces.swift (Spaces bridge)
               discrete/Builtins/WindowMover.swift (monitor placement)
    does:      the same intelligent opening used for .app resources and
               app search results. if A is displayed on the pointer's
               current desktop, cycle to A's next desktop on that monitor
               in Mission Control order, wrapping around. multiple windows
               on one desktop cycle focus in stable window-id order before
               advancing to the next desktop. with only one local desktop,
               focus wraps to its first window without switching desktops.
               all-desktops windows don't create extra desktop stops.
               opening from another app focuses A's first local window.
               if A isn't displayed locally and there are multiple monitors,
               bring the first window not displayed on any monitor to the
               pointer's current desktop. minimized/hidden windows qualify.
               if all are displayed, bring the first window instead.
               "first" means Mission Control desktop order, then window id.
               with one monitor and no local window, focus the first existing
               window on its desktop. with no windows, launch/reopen A and
               place its first window on the pointer's monitor and desktop.
               size/relative placement/fullscreen handling reuse WindowMover.
    platform:  needs Accessibility permission. Spaces enumeration, movement
               and targeted focus use optional private macOS APIs resolved
               at runtime. switching desktop is explicit and verified before
               focusing; accepted window-focus calls alone don't switch Spaces.
               visible window ids come from the on-screen inventory (the full
               inventory may omit visibility flags). moves are also verified.
               native fullscreen destination Spaces cannot accept another
               app's window. if a move fails, focus the existing window;
               if Spaces information is unavailable, use normal app opening.
               no SIP changes or external window manager are required.
    checks:    tests/ApplicationOpenPolicyTests.swift covers selection without
               changing desktops. tests/application-opening-manual.txt covers
               live macOS checks (Space movement needs a GUI session).


toggle full-screen
    id:        toggle-full-screen
    argument:  none
    exits:     yes
    code:      discrete/Builtins/WindowFullscreen.swift
    does:      toggles native macOS fullscreen of the frontmost app's focused
               window via AXFullScreen. a normal window enters fullscreen;
               a fullscreen window leaves it. requires Accessibility permission.
               does nothing if there is no focused window or the window doesn't
               support changing fullscreen. discrete exits in either case.


ADDING A BUILTIN

1. discrete/Builtins/BuiltinToolkit.swift
       add a case to BuiltinFunction.Behavior, set staysActive and
       argumentPrompt for it, and add an entry to BuiltinToolkit.root
       (or a folder) with a new, permanent id. never change or reuse an id:
       saved graphs refer to builtins by id.
2. put the implementation in its own file in discrete/Builtins/ and call it
   from BuiltinRunner.run (or from DiscreteGraphStore.run if it changes
   discrete's own state, like search).
3. describe it in specs.txt under "builtin toolkit" and list it here.

REMOVING A BUILTIN

Delete its entry from the toolkit, but leave its id unused forever. Saved
functions that point to it stay in the user's graph, dimmed and marked
"(builtin not available)".
